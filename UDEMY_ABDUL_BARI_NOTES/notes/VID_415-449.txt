Prim's Algorithm
choose the minimum edge and connect or can choose any vertex
now choose the next minimum edge from the two connected vertices only to form a continuous MST
have an adjacency matrix with costs for the array
select an edge and check the minimum cost edge associated with it and select that
also maintain the same boolean selected array to keep check of cycles
have an array near of size equal to number of vertices
In near array compare whether the vertices are closer to the selected vertices or not and fill it up with the selected vertices' number
if same value then can choose either
dont fill those indexes which are already selected
search through the near array to find the minimum cost edge and choose that pair
the new pair becomes the updates U and V 
update the near and selected array again
if after selection of new vertex in the near array any cost is less than the previous values then update the array with that vertex 
again scan the near array for minimum cost

Maximum SubArray Sum 
    find the portion of the given array that gives the highest possible Sum
    Method 1:-
        use two pointers i and j at index zero
        find sum then move j forward till the end
        similarly after j reaches the end move i and j both to i+1 and iterate j again
        maintain maxSum=MIN_INT and update it again and again and return it in the end
        takes O(n^3) 
    Method 2(Better and Improved):-
        instead of inner loop just use a local sum variable just drops the complexity down to O(n^2)
    Method 3(Using DP):-
        same procedure but we want the arry of highest values to consider 
        while iterating now dont add all elements to the prev sum WHEN SUM BECOMES NEGATIVE and take that value as it is
        take the max out of all those values and that is our answer
        have a single for loop
        with s[0]=a[0] if s[i-1] is negative then s[i]=a[i] else s[i]=s[i-1]+a[i]
        return the max element from this array
        takes O(n) time and space
    Method 4(Using Kadane's Algorithm):-
        instead of maintaining an array of sums we just use a variable to store the prevsum
        also have a the MaxSub to store the locally better sum out of the current and prev sum
        compare prevsum like method 3 but compare maxsub to prevsum
        O(n) time and O(1) space
        have a substart and end variable if you wish to know the index of the SubArray as well
    Method 5(Using Divide and Conquer):-
        find max subarray for LHS and RHS and combining both sides and comparing all 3 and return the greatest one
        have leftmax rightmax and crossSum to compare
        crossSum take low mid and high as arguments
        crossSum finds leftsub and righsub from middle and returns the added value
        takes O(nlogn) time

N-Queens Problem
N queens on a N X N chessboard arranged such that no 2 queens attack each other (where N is a power of 2)
mirror image of a solution is also the correct solution for a nQueen problem
use a 1D array just to store the positions of the queens
then iterate over them recursively with a condition to check for if valid which shall check if the queen is under attack or not by previous queens
to check validity run the for loop for k-1 times to check with all other previous queen's positions
    if j value of prev queen is same as j value of the current queen then return false
    if i-j = k-l then they are on the same diagnol and return false
    if i+j = k+l then also they are on the same diagnol and return false
    i. e. i - k = |j-l| then it lies on the diagnol and return false
    O(n^n)
